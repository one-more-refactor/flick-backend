## 2026-07-16 - [Secure X-Forwarded-For IP Parsing to Prevent Rate Limit and Referral Spoofing]
**Vulnerability:** The application was extracting the first (leftmost) IP from the `X-Forwarded-For` header to identify the client for rate limiting and referral anti-abuse checks. Since reverse proxies like Caddy append the actual client IP to the right end of the `X-Forwarded-For` header, any client could completely spoof their IP by sending a custom `X-Forwarded-For` header with arbitrary IPs. This allowed them to trivially bypass all rate limits and referral restrictions.
**Learning:** This vulnerability existed because of a misconception that the first IP in `X-Forwarded-For` represents the real client when using a reverse proxy. However, because clients can arbitrarily inject `X-Forwarded-For` headers, and proxies only append/overwrite on the right, the leftmost entry is only untrusted user input.
**Prevention:** To parse `X-Forwarded-For` securely behind trusted proxies, traverse the IP list from right to left (most recent proxy to oldest), skipping all trusted internal/local proxies (e.g., loopback, private networks), and stop at the first non-trusted IP. Fall back to the rightmost/last IP if all are trusted proxies. This completely neutralizes client-side spoofing.
